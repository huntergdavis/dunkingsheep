# Rust desk cutover staging

Build the reviewed `ds-desk` binary from the exact accepted commit, and stage it in a new immutable release containing the matching built `ui/dist` and channel example. Keep the current release and Python virtualenv intact. Substitute the release directory in `rust-web.conf` before installing it as a web-only drop-in. The drop-in preserves the existing web unit's desk data, channel, token and bind settings, and switches `DUNKINGSHEEP_DIR` from the legacy release path to daemon state. It does not switch the shared `current` symlink: the Telegram unit also uses that path and must retain its Python runtime. Review the effective unit, UI, token file, daemon socket and listener before any switch. This file is a staging example; it is not installed by the build.

The owner coordinates the web service stop, drop-in installation, daemon reload and restart, then verifies the essential desk flows and process identity. Save the effective unit and existing drop-ins first. Rollback stops the web unit, removes this drop-in, reloads systemd, and restarts the original web unit; verify Python is listening and the desk works. No shared symlink or state files are changed. Existing routes deferred by the Rust desk and the pending delivery watcher require separate acceptance before cutover.
