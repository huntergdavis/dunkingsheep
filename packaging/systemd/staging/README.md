# Rust desk cutover staging

Build the reviewed `ds-desk` binary from the exact accepted commit, and stage it in a new release containing the matching built `ui/dist` and channel example. Keep the current release and Python virtualenv intact. The drop-in `rust-web.conf` expects the binary at `current/ds-desk`, preserves the existing web unit's desk data, channel, token and bind settings, and switches `DUNKINGSHEEP_DIR` from the legacy release path to daemon state. Review the effective unit, UI, token file, daemon socket and listener before any switch. This file is a staging example; it is not installed by the build.

The owner coordinates the service stop, release symlink switch, drop-in installation, daemon reload and restart, then verifies the essential desk flows and process identity. Save the previous `current` target and effective drop-ins first. Rollback stops the web unit, removes this drop-in, restores the previous `current` target, reloads systemd, and restarts the web unit; verify Python is listening and the desk works. No state files are removed. Existing routes deferred by the Rust desk and the pending delivery watcher require separate acceptance before cutover.
